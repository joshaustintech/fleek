# Fleek 0.1.0

Fleek 0.1.0 is a native macOS arm64 CLI for explicitly selected Ruby checks. The verified archive is `fleek-0.1.0-macos-arm64.tar.gz`, SHA-256 `025449a33a9028a87c7e26b7618cca72077ecfaffc6a5911a0e75fa478e19ef3`. GitHub release `v0.1.0` was built from source commit `f5380ebad9e07958f659a1820d03060622d58b97`; the published archive was retrieved, matched by digest, extracted, and passed the installed CLI contract.

## Supported behavior

Select `flay:StructuralDuplication`, `reek:ClassVariable`, or both with `--checks`. Fleek analyzes Ruby 4 grammar; analyzed source need not compile as Spinel. Coverage is bounded. Unsupported syntax, checks, or configuration are reported explicitly, and incomplete analysis exits 1. Findings exit 2; complete clean analysis exits 0. Flay findings, score, source locations, and coverage were compared semantically against Flay 2.14.4; Reek ClassVariable was compared against Reek 6.6.0. Fleek's stdout format intentionally differs from both references.

The pinned 25-file Rails sample currently has useful matching findings but incomplete Flay coverage (0/25 fully analyzed), so this release does not claim full Rails Flay parity. The reference identity, exact comparison, and differences are in `docs/research/rails-project-parity.md`.

## Runtime evidence

On macOS arm64 27.0.1, the cold-process p95 was 3.897 ms for the complete Flay fixture workload (reference 178.776 ms), 6.606 ms for Reek ClassVariable on the pinned 25-file Rails corpus (reference 376.211 ms), and 4.323 ms for combined checks (reference 693.700 ms). Each comparison uses identical inputs, selected configuration, and semantic findings; Flay's finding exit status intentionally differs (Fleek 2, Flay 0). These are 20 fresh-process samples per variant with natural filesystem caches, not cache-eviction measurements. Details and raw samples are in `docs/research/cold-runtime-2026-10-15.md`.

## Installation

Download and extract the macOS arm64 archive, then run `./fleek --help` or follow the included `README.txt`. It is an ad hoc linker-signed binary and is not notarized. It links only to macOS `libSystem` and needs no Ruby or reference analyzer at runtime.
