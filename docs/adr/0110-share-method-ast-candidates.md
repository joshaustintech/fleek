# ADR 0110: Share normalized AST candidates across method scopes

Flay compares method subtrees with structural hashes and node mass. Fleek's top-level method path instead compared statement tags, so calls with arguments were rejected and mass/identity behavior duplicated the class-method adapter.

Use the same bounded normalized AST tree and positional-parameter rules for top-level methods and class methods. Structural tree markers determine shape; supported node values and parameter names/defaults determine identical versus similar; the shared mass calculation counts AST nodes and excludes the same wrappers. Unsupported nodes still fail closed. This removes the separate statement-tag model and gives both method scopes one candidate algorithm.

Public contracts compare Flay 2.14.4 and Fleek for methods containing argument calls (mass/score 16), required parameters (mass/score 14), differing required arities (mass/score 12), optional parameters and differing defaults (mass/score 52), bounded if/else control flow (mass/score 62), local-variable writes and identity (mass/scores 38 and 16), boolean OR expressions (mass/score 34), and conditional returns (mass/score 44). Ruby 4 logical-and variants compare different operands and statement positions. Focused mutations disable argument-child traversal, parameter acceptance, default identity, conditional traversal, local-write identity, OR traversal, or return traversal and must break the compiled CLI contract. Support remains bounded; other Flay method forms are tracked by ticket 22.
