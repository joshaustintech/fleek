# Isolate Flay timeout analysis

Accepted for Ticket 120.

Flay 2.14.4 applies its integer-second timeout around each individual parser call. Fleek's parser is a synchronous native Prism call; asynchronous interruption from inside the same process is unsafe. For an explicitly supplied positive `--timeout`, run timed Fleek analysis in an isolated worker and start a separate Fleek timer child. The parent waits for its worker; if the timer expires first, it writes an expiry marker, kills only that worker, and exits. The hidden timer command requires an inherited parent marker; direct invocation without that marker is rejected. If analysis finishes first, the parent stops and reaps the timer. Preserve successful output exactly; on expiry discard partial output and report selected coverage as incomplete. Scale the whole-selection budget by included source count. This avoids marking a multi-file run incomplete merely because its total duration exceeds one per-file allowance. Zero and omitted timeout use the direct path; the omitted Flay default is not imposed on Fleek because process isolation adds measurable cost to ordinary scans. See [ADR 0234](0234-keep-untimed-flay-runs-on-direct-path.md). Per-file continuation and preservation of findings from unaffected files remain in [issue 128](../../.scratch/fleek/issues/128-flay-per-file-timeout-continuation.md).
