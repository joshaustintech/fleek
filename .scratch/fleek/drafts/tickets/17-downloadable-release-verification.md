# 17: Downloadable release verification

**What to build:** Users can obtain the actual downloadable first release and reproduce its documented native behavior and supported scope. Parent specification: Standalone native release and performance evidence.

**Blocked by:** 15 Cold runtime evidence; 16 Standalone archive installation.

**Status:** open
**Publication:** draft; proposed triage ready-for-agent after review.

- [ ] Publish the verified versioned artifact through the project's authorized release destination; include coverage, deliberate compatibility differences, reference identities, installation guidance, and truthful performance evidence.
- [ ] Verify the release asset actually exists and is downloadable; compare retrieved artifact identity against the proven archive.
- [ ] Extract the retrieved artifact and execute native help/version plus representative clean/finding/incomplete cases; record results separately from source-build proof.
- [ ] Final evidence names exact release, artifact, source commit, remote/main push result, supported scope, and any remaining limitation.
- [ ] A missing asset, failed install, unmet accepted release target, or missing runtime proof keeps delivery incomplete; no text receipt or build success substitutes for it.
